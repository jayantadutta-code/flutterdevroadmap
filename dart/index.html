MODULE 1 • POINTS 1-3

YAML Basics, Comments & Key-Values

1. YAML Basics

YAML (YAML Ain't Markup Language) is a human-readable data serialization language. It is commonly used for configuration files, Kubernetes, Docker Compose, CI/CD pipelines, Ansible, Flutter's pubspec.yaml, GitHub Actions, and many more.

File Extension
.yaml
.yml

YAML Example
name: Jayanta
age: 22
country: India

2. Comments

Comments Syntax
# Single-line comment
name: Jayanta

# Multiple comments
# User Profile Info
# Created by Admin
country: India

3. Key-Value Pairs

Key-Value Example
language: YAML
creator: Clark Evans
year: 2001

MODULE 1 • POINTS 4-5

Strings & Numeric Scalars

4. Strings & Quoting

String Syntax
# Unquoted string
name: Jayanta

# Double Quotes (supports escape sequences like \n and \t)
bio: "Flutter &\nDart Developer"

# Single Quotes (literal string, preserves backslashes)
path: 'C:\Users\Jayanta'

5. Numbers (Int, Float, Scientific)

Numeric Types
age: 22          # Integer
pi: 3.14159      # Float
distance: 2e5    # Scientific (evaluates to 200000)
temp: -12        # Negative Number
Quoting Rule: Strings in YAML don't require quotes unless they contain special characters like colons : or brackets [].

MODULE 2 • POINT 9

Nested Lists & Matrices

9. Nested Lists & Matrices

Nested List & Matrix
students:
  - Jayanta
  - Rahul
  - Amit

# Matrix (List of Lists)
matrix:
  - [1, 2, 3]
  - [4, 5, 6]
  - [7, 8, 9]
List Rule:
Always include a space after the dash (- ). A dash without space (e.g. -12) is parsed as negative number!

MODULE 7 • POINTS 31-32

Best Practices & YAML vs JSON

31. Production Best Practices

  • ✔ Standardize on 2 spaces per level
  • ✔ Keep nesting levels shallow
  • ✔ Quote strings with colons or special symbols
  • ✔ Add comments for complex configurations

32. YAML vs JSON Comparison

Feature YAML JSON
Human Readability ⭐⭐⭐⭐⭐ ⭐⭐⭐
Supports Comments ✅ Yes (#) ❌ No
Syntax Overhead Minimal Brackets & Quotes
Primary Use Config Files API Data Transfer
